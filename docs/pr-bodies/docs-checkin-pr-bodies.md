## Summary

Four commits on this branch wire the existing offline `docs/pr-bodies/`
directory into the contributor workflow so future contributors no longer
need to be told about it in chat or in cross-repo scrollback. The branch
also backfills the two body files that were still missing from the bulk-
deploy stack (`test/fix-lib-api-parser` and `test/jest-provider-helper`),
audits the 30-issue `ISSUES.md` tracker against the actual `main`
codebase, and lands a CI guard so the body-file contract cannot drift
silently in the future.

## What's changed

### `docs/pr-bodies/` (corpus)

- **`docs/pr-bodies/test-fix-lib-api-parser.md`** (new, +44) — corpus body
  for branch `test/fix-lib-api-parser` (commit `d4949f3`). Removes the
  orphan `redeemReferralCode = (` declaration block at the end of
  `lib/api.ts` that was producing a `TS1005: Expression expected` parse
  error and masking several test suites from CI. `lib/api.ts` is +35/-19.
  Backfills the second of the two "missing" branches from prior chat
  scrollback.
- **`docs/pr-bodies/test-jest-provider-helper.md`** (new, +63) — corpus
  body for branch `test/jest-provider-helper` (commit `81f1639`).
  Adds a `renderWithProviders(ui, options)` helper at
  `__tests__/setup-providers.tsx` that wraps renders in `SWRConfig`,
  `ToastProvider`, and `WalletProvider` and re-exports the standard
  `@testing-library/react` utilities so callers can swap one import to
  migrate. Adds a `testPathIgnorePatterns` entry to `jest.config.js`
  (so Jest doesn't treat the helper as a zero-test suite under
  `--ci`) and a `beforeEach` to `jest.setup.ts` that clears
  `localStorage` and `sessionStorage` for storage-bleed isolation.
  Total +98/-0 across the three files.
- **`docs/pr-bodies/README.md`** (modified, +5/-5) — Files table
  extended from 4 to 6 entries; the "Related" section rewritten to
  drop branches that have since been backfilled and to clarify the

- **`docs/pr-bodies/docs-checkin-pr-bodies.md`** (new, this file) —
  self-referential corpus body for the bundle on this branch. The
  `<!-- Title: ... -->` value above matches the PR's
  `--title "..."` argument verbatim so future rebases can regenerate

## Out-of-scope (NOT introduced by this PR)

The `.gitignore` change adds `/data/` (anchor-to-root) which the local
dev workflow writes to during `housekeep` in `lib/referralStore.ts`.
If you have a pre-existing `data/` directory at your project root
before pulling this change, `git status` will show it as untracked
but harmless — your `housekeep` continues to write there, and the new
ignore means it no longer pollutes your diffs.

Pre-existing items still gapped per the new `ISSUES.md` status audit:

- **#26** — hook test coverage for `useScout`, `usePayToContact`,
  `usePlayer`, `useValidator` is open in a separate follow-up.
- **#27** — page-level component tests for `ScoutDashboard`,
  `PlayerDashboard`, `PlayerProfile` are open.
- **#30** — `DEVELOPMENT.md` is in skeleton form; the "common
  errors and their solutions" subsection needs enrichment.
- **#23** — the ErrorBoundary "Try again" recovery button is
  partially locked in by `test/error-boundary-production`; only
  the recovery-button aspect is unverified.

These are explicitly out-of-scope so reviewers can sign off on the
bundle cleanly. Each fits the existing stack-and-deploy pattern this
branch set up.
